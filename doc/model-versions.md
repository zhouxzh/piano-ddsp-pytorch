# 模型版本命名与 v2 音质分析

记录日期：2026-07-23

## 版本定义

| 对外版本 | 当前 ONNX 文件 | 定位 | 试听目录 |
| --- | --- | --- | --- |
| v1 | `exports/piano_current_fixed.onnx` | 修复混响后的旧结构，当前人工试听基线 | `exports/midi_tests/v1/` |
| v2 | `exports/piano_ddsp_v2.onnx` | FiLM、深层单音网络、更多谐波/噪声控制和 FDN 混响的实验结构 | `exports/midi_tests/v2/` |

`current-fixed` 从本记录起正式称为 **v1**。ONNX 文件名暂不改动，因为现有脚本、部署 JSON
和外部调用可能已经引用该路径。新导出的 JSON 包含 `release_version`，后续试听输出、A/B 报告
和文档使用 `v1`/`v2`。内部参数 `model_variant=current` 也暂时保留，用于兼容旧 checkpoint。

版本号只表示结构迭代顺序，不自动表示音质排序。当前 v2 应视为 `v2-experimental`，在固定
测试集的人工盲听超过 v1 前，不应替换 v1 基线。

## 为什么 v2 目前不如 v1

当前证据不支持“v2 没有训练完成”。v2 的完整 phase-1 训练已完成 40,000 步，导出使用
`best.pt`（第 32,000 步，记录的验证损失 `7.7191`）。v1 导出使用 phase-1 `best.pt`
（第 38,000 步，记录的验证损失 `10.9718`）。但是这两个总损失不能直接当作跨结构的音质
排名：两版的混响参数化和正则项不同，而且每轮只取固定的前 16 个验证片段，覆盖面不足。

同一批 10 首 MIDI、同一钢琴 embedding、warm-up、释放尾音和噪声种子的 ONNX 渲染统计显示：

| 指标（v2 / v1） | 10 首平均 | 中位数 | 范围 |
| --- | ---: | ---: | ---: |
| 干声 RMS | 5.94x | 5.78x | 4.83x - 7.08x |
| 谐波 RMS | 6.15x | 5.95x | 5.02x - 7.27x |
| 噪声 RMS | 3.76x | 3.26x | 2.51x - 7.53x |
| 混响后 RMS | 2.95x | 2.90x | 2.65x - 3.47x |

试听 WAV 最终会各自峰值归一化到约 `-1 dBFS`，因此这些差异不会只表现为“更响”。它们说明
v2 的幅度、谐波和噪声控制标定与 v1 明显不同；归一化后，包络、瞬态和声部叠加关系仍会改变。
v2 的平均峰均比也从 v1 的 `18.62 dB` 降至 `17.64 dB`，动态略更密。

主要原因按当前证据排序如下：

1. 训练目标与听感没有完全对齐。多尺度频谱损失可以下降，但没有直接约束响度标定、起音瞬态、
   力度响应、声部叠加动态和主观钢琴音色。
2. v2 同时更换了上下文网络、单音控制网络、谐波数（96 到 128）、噪声频带（64 到 96）、
   非谐性模型和混响模型。一次改变过多，当前实验无法从结果中隔离是哪一项导致退化。
3. v1 使用每个钢琴 embedding 的学习型 24,000 点 IR，并以 `0.25` wet gain 输出；v2 改为 9 个
   控制量驱动的宿主端 FDN。FDN 控制目前只有很弱的平方正则，没有针对衰减时间、直达声/混响比、
   早期反射或尾音频谱的感知约束，房间响应更难稳定到预期音色。
4. 当前模型选择只检查每轮固定的前 16 个 validation batch，可能偏向少数曲目和局部片段。
   `best.pt` 因而代表该小样本上的频谱损失最佳，不代表 10 首试听集或人工评价最佳。
5. v2 当前导出仍是 phase 1，`f0_hz` 合同为单琴弦。双琴弦失谐和第二阶段频率参数并没有成为
   这次试听优势，因此不能把“结构里预留了双弦”当作已经实现的音质收益。

## 后续版本规则

- v1 保持为质量基线，不再使用 `current-fixed` 作为对外版本名。
- v2 在盲听和跨曲目指标超过 v1 前保持实验状态，不覆盖 v1 导出物。
- 后续实验一次只改变一个模块，建议顺序为：先校准干声幅度与力度动态，再比较 96/128 谐波和
  64/96 噪声频带，最后单独比较 v1 IR 与 v2 FDN。
- 每个候选版本必须使用 `midi/` 的固定内容签名测试集，保留未归一化 RMS、峰值、峰均比、
  复音溢出记录和人工评分。模型选择应使用跨曲目均衡验证集，而不是固定前 16 个片段。
- Ascend 310B 的神经图合同仍保持 FP32、opset 13、batch 1、单个 250 Hz 控制帧和显式 GRU
  状态；谐波、噪声与混响 DSP 继续位于 ONNX 图外。版本命名变化不改变部署输入输出合同。
